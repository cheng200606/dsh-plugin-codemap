- 产出主文档：`docs/qoder-repo-wiki-research-and-dsh-plugin-design.md`（v0.1 设计草案，约 1680 行）。

- 核心结论：Qoder Repo Wiki = 代码索引 + 结构化页面 + 知识卡片三层资产；本地多 Agent、`wiki_plan.yaml` 规划、基于 Git diff 的增量更新、导出到 `.qoder/repowiki` 并随 Git 共享。
- 插件设计：`dsh-plugin-repowiki`，注册 `ctx.repoWiki` 服务；3 个模型工具（`wiki_search`/`wiki_read`/`wiki_generate`）+ `/wiki` 命令；6 阶段流水线（Preflight→Index→Plan→Evidence→Write→Verify→Persist）；产物 `.dsh/repowiki`。
- 优先级：P0 扫描/索引/规划/8–12 页生成/持久化/检索/引用校验；P1 增量更新/Job/多 Agent/知识卡片；P2 UI/Qoder 互操作/多语言/混合检索。
- 里程碑：M0 1 周、M1 4 周、M2 4 周、M3 4 周、M4 4–6 周，合计约 17–19 人周。
- 下一步：M0 Spike（20k–50k LOC 仓库，单页生成 + 引用校验 + 成本基线），并定 30 个黄金问题。

## dsh-plugin-repowiki 实现、安装与端到端测试（同日续）

- 交付：`plugin/dsh-plugin-repowiki/`（可安装 Cordis bundle，17 个源文件（`index.js` + `src/` 16 个）+ package.json + cordis.patch.yml + locale/en|zh.json + icon.svg + README + `test/{local-e2e,probe-coverage,debug-export}`）。
- 实现取舍（与设计文档的差异已在交付报告 §6 逐条列出）：
  - 纯 ESM JavaScript、**零第三方依赖**：profile 内无 `tsc`、无 `@deepseek-ai/cordis`、无 `@deepseek-ai/dsh-tools`，故不 import cordis（服务用 `ctx.provide('repoWiki', service)` 注册），工具直接注册**裸 JSON Schema** 定义。
  - 生成过程**不调用模型**：证据（EvidencePack）由代码算出、引用由真实行号反查 ⇒ 离线可跑、结果可复算、引用可验证（实测 89/89 有效）。
  - 增量更新基于**每页输入哈希**而非 `git diff -M`（安全约束：不执行仓库脚本/进程）。
- 安装：`plugin_manager action=install_bundle target=<插件绝对路径>` → `application: applied`、`warnings: []`、pnpm `exitCode 0`；profile 内以 **junction** 链接到源目录（改代码即时可见；刷新运行实例用 `set_bundle enabled=false` → `true`，`install_bundle` 对已安装包会返回 `already-installed`）。
- 测试：本地 `node test/local-e2e.mjs` **16/16 PASS**；宿主内由子 Agent 真实调用 `wiki_generate`（full → update）→ `wiki_search` → `wiki_read` 全部成功，磁盘生成 `.dsh/repowiki/`（15 个文件、8 页、1 知识卡、**89 条有效引用 89/89、去重覆盖 14 个源文件、8 页全 `fresh`**）；增量模式实测 `written=0 / skipped=8`、耗时 208 ms → 67 ms。
- 验收轮次中暴露并修复的关键缺陷（详见交付报告 §5.1 的 16 项）：`util.js` 混入裸 NUL 字节导致被宿主判为二进制；`output.render` 只输出散文导致模型看不到 schema（改为「摘要 + ```json 块」）；`page_id` 示例写错；frontmatter 与元数据 `status` 不一致；落地页/规划文件/知识卡不在检索语料内；工具耗时与元数据耗时不同源；**证据装配是「按类别切配额再整体截断」，导致少数文件吃满配额、其余文件一条结论都轮不上**——改为广度优先装配（语义结论 → 每文件第一条符号结论 → 文档结论 → 覆盖兜底 → 深度），配额从 `MAX_CLAIMS 8 / MAX_KEY_FILES 6` 放宽到 `12 / 8`。
- 自证通道：插件在每次运行时写 `<outputDir>/meta/runtime.json`（注册的服务/工具/命令/提示词段、生效配置、宿主 node/平台/时间、lastRun），这是本次最有效的验证通道。
- 交付报告：`docs/dsh-plugin-repowiki-delivery.md`（§0 一页纸结论 + §1 交付物 + §2 功能范围 + §3 安装配置 + §4 测试结果 + §5 问题清单 34 项（16 实现缺陷 / 12 宿主 API 坑 / 6 流程问题，另附 3 个测试脚本自身 bug）+ §6 差异勘误 15 项 + §7 限制 + §8 复现步骤）。
- 副产物：`docs/cordis-plugin-api-reference.md`（Cordis 4.0.5 插件 API 源码级参考）。
- 实机版本勘误：设计文档写的 DSH `0.2.2-alpha.2` / cordis `4.0.6-alpha.1` 与实机不符；实机为 DSH `0.2.1-rc.5` / cordis `4.0.5`，已以实机为准。
