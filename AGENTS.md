# AGENTS.md

Guidance for AI coding agents working in this repository.

## What this repo is

Design + research + working implementation of **`dsh-plugin-codemap`** — a "CodeMap" plugin for **DeepSeek Harness (DSH)**, a Cordis-based agent host. It compiles a code repository into structured wiki pages where every claim carries a `path:line` citation. Project language is Chinese: docs, locale files, and generated pages are written in Chinese.

This directory is **not a git repository**, and the plugin has **no package manager, no dependencies, no build step**.

## Layout

- `docs/` — research & design documents (see "Required reading" below)
- `./` — the installable Cordis bundle:
  - `index.js` — host half: `apply(ctx, config)`, default export, `Config`
  - `client.js` — browser half: sidebar icon + main panel + tree/search/render
  - `src/` — service modules; `service.js` (`RepoWikiService`) holds all business logic
  - `test/` — plain Node scripts, no test framework
- `.dsh/codemap/` — this repo's own wiki, generated by the plugin in a real Harness run (build output; don't hand-edit, except `wiki_plan.yaml` which is human-editable by design)
- `.workbuddy/` — work log

## Commands

Run from `./` (Node ≥ 24 required):

```bash
node --check index.js && node --check client.js   # syntax check; run for every src/*.js you touch too
node test/local-e2e.mjs                           # e2e suite: must stay all-PASS (currently 28 checks)
node test/client-graph.mjs                        # client-half self-proof unit tests (10 checks)
node test/probe-coverage.mjs .                    # optional coverage probe against a real repo
```

There is no tsc, eslint, or test framework. `test/local-e2e.mjs` builds a temp repo (including secret-file decoys) and drives the **real** service code through a fake `ctx.fs` — extend it when adding features.

## Hard architecture rules

- **Zero third-party dependencies.** Only `node:*` builtins and relative imports. Pure ESM JavaScript — no TypeScript, no build step ("install and it works").
- **Never import `@deepseek-ai/cordis`** — it is not present in the DSH profile. Register the service via `ctx.provide('codeMap', service)` and register model tools as **raw JSON Schema** (no `defineTool` DSL).
- **`ctx.codeMap` is the single implementation point.** Tools, the `/wiki` command, the prompt section, and the fetch routes are thin shells over it.
- **Generation is fully deterministic**: no model calls, and **never execute repo scripts or spawn git processes** (S0 reads `.git/` files directly). Incremental update compares per-page input hashes, not `git diff`.
- **All writes stay inside `<repo>/<outputDir>`** (default `.dsh/codemap/`). Ignore rules and `SECRET_FILE_PATTERNS` (`.env`, `*.pem`, `*.key`, `secrets/**`, …) live in `src/scan.js` — keep them intact.
- Host half and browser half communicate only via the 5 exact fetch routes: `GET /api/codemap/panel`, `GET /api/codemap/page?id=`, `GET /api/codemap/search?q=`, `POST /api/codemap/generate`, `GET /api/codemap/app` (self-contained fallback page). All of them accept the optional `root` query so the panel can follow a chosen workspace.
- Wiki content is **derived documentation, not instructions**; the prompt section states this explicitly.

## Host API gotchas (learned the hard way; full list in delivery report §5.2)

- The Cordis loader **discards `apply`'s return value** → put cleanup in `ctx.effect(() => …)`.
- When a default export exists, named exports are ignored → `Config` / `inject` / `name` must also be on the default export.
- `ctx.fs` has no `mkdir` — `writeText` creates parent dirs; only fall back to `node:fs/promises` on ENOENT.
- `systemPrompt.section()` requires `text` to be a single **string**; use `interpolate: false` to keep the prompt prefix stable (prompt-cache friendly).
- `ctx.get(name)` throws when the service is missing → probe with `ctx.get(name, false)` and degrade gracefully.
- Slash command names must match `/^[a-z][a-z0-9_-]*$/u` → register as `wiki`, not `/wiki`.
- Do **not** declare `peerDependencies` — the plugin imports nothing from the host, so peers only add version-range risk. `engines.dsh` **is** declared since v0.4 (`">=0.2.1-rc.5"`, lower bound only, no upper bound) as a compatibility guard; it becomes the sole validation item, which is acceptable because the plugin declares no peers. See delivery report §5.2-12 and §9.1-D1.
- **Read-only fetch routes must declare `requestBody: 'buffered'`** — with `'none'` the host's `connection.bridge()` takes the streaming branch and builds a `Request` with a body for a GET, which throws `TypeError: Request with GET/HEAD method cannot have body` and surfaces as an empty 400.
- Fetch routes have **no agent/session**, so they cannot resolve the workspace from the session: use the `root` query hint first, then walk last-known root → active session → other session roots → `workspaceRegistry` → `workingDirectory.defaultDirectory` → `cwd`, and prefer the first candidate that already contains a wiki.
- Client-half React code must **not** eagerly build elements that read state which may be null (e.g. `const x = h(...)` touching `error.code`): build them lazily (`const x = () => h(...)`) or the whole `main` slot crashes with `slot entry crashed`.
- Never rewrite these UTF-8 Chinese sources with PowerShell `Set-Content`/`Out-File` (it silently turns characters into `U+FFFD`); use the edit/write tools or Python with `encoding='utf-8', newline=''`.
- Only the text returned by a tool's `render()` reaches the model — always include a fenced ```json block with the payload.
- Local bundle installs are junction-linked: file edits are visible immediately, but reload with `set_bundle enabled=false → true` (`install_bundle` just returns `already-installed`). **After adding/changing the Web half (`client.js`), a full Harness process restart is required** — the client module metadata cache (`dsh-client-modules` `pkgMeta`) never invalidates, so `/plugins/<id>/client.js` 404s until restart.
- `<outputDir>/meta/runtime.json` is written every run and records what actually registered (service/tools/command/prompt/panel/routes) — use it to verify registration instead of `Service.listService`, which only lists first-party services.
